# AGENTS.md

NYX: zero-knowledge post-quantum messenger. pnpm monorepo: `web` (React 19 + Vite 8), `server` (Express 5 + Prisma 7 + Redis bridge), `marketing` (Astro), `packages/shared` (`@nyx/shared`), `server/transport-sidecar` (Rust WebTransport).

## Commands that matter

- **`@nyx/shared` is consumed from `dist/`** — after editing `packages/shared/src`, run `pnpm --filter @nyx/shared run build` BEFORE typechecking web/server or the changes are invisible.
- Build: `pnpm -r run build` (root) — runs web `tsc -b && vite build`, server `tsc`, marketing `astro build`.
- Unit tests: `pnpm -r --if-present run test`. Server = `node:test` via `tsx` (files listed explicitly in server `package.json`; jest config is dead, do not use). Web = vitest.
- Typecheck: `npx tsc --noEmit` per package. After `pnpm install` or dep updates, run `npx prisma generate` in `server/` first or server tsc fails with missing `PrismaClient` export.
- **Lint = oxlint — satu-satunya linter** (`pnpm run lint` → per package `oxlint src`; config `.oxlintrc.json` di root). ESLint sudah **dihapus sepenuhnya** (2026-10-15): ketiga `eslint.config.js`, 20 devDependency eslint/*, dan semua direktif `eslint-disable` lama tidak ada lagi — jangan dihidupkan kembali (`typescript-eslint` menolak TS 7.0). Rule level `error` = kelas bug/keamanan dan WAJIB 0 (job CI `lint` blocking); kategori `correctness` = `error` sejak 2026-10-14 (bersih, 0 error). Sisa temuan hanya `no-unused-vars` yang sengaja `warn`; jangan naikkan rule itu ke `error` sebelum angkanya 0. `npx oxlint <path>` untuk cek satu berkas cepat.
- **Direktif penekan memakai sintaks oxlint**: `// oxlint-disable-next-line <rule>` dan **harus persis di baris tepat di atas kode** — direktif yang menghadap komentar tidak menahan apa pun (ini pernah terjadi di `server/src/utils/logger.ts`: dua direktif bersebelahan, yang benar-benar bekerja justru yang `eslint-`). Cari direktif mati dengan `npx oxlint src --report-unused-disable-directives`.
- Fuzz parsers (WS-G(5)): web `pnpm --filter nyx-web run fuzz:parsers` (`fuzz:parsers:hour` for the 1-hour gate); sidecar `cd server/transport-sidecar && cargo test` then `NYX_FUZZ_SECONDS=3600 cargo run --release --bin fuzz-framing`. Deterministic (xorshift, no `Math.random`) — a finding is reproduced from the printed seed. Docs: `docs/11` §11.1c.
- Alert drill (WS-G(2)): `scripts/drill-alerts.sh` — `promtool check config`/`check rules`/`test rules` (every rule needs a firing AND a non-firing case), plus a metric contract (any `nyx_*` named in a rule must be declared in one of the four committed sources: `server/src/utils/metrics.ts`, `server/kt-query/cmd/nyx-kt-auditor/metrics.go`, `server/kt-query/metrics.go`, `server/transport-sidecar/src/metrics.rs`) and coverage (a new rule without a drill case fails). `promtool` is fetched (pinned 3.15.0) into `.cache/` if absent; pass `PROMTOOL=<path>` for offline, `SKIP_LIVE=1` to skip the live `/metrics` scrape layer. Runs per-PR (CI job `alerts` + the scrape layer in `e2e`).
- Relay load test (WS-G(3)): `scripts/load/run-relay-load.sh` (`BASE_URL=…`, `NYX_MAX_VUS=…`). It checks the API is up, provisions an idempotent test account/conversation (`server/scripts/load-test-user.ts`), runs a 5-VU SMOKE first (auth/CSRF failures otherwise look like light load), then the full k6 profile. **Writes messages** — never point it at prod. Last measured 500 VU: send p95 74 ms, fetch p95 69 ms, 0% errors.
- Cross-implementation DR oracle (WS-G(6)): `cd tools/dr-oracle && go run . -check` gates the committed vectors against regeneration (`-write` rewrites them, `-gen` prints). `go build/vet/test` + `-check` plus `web/src/lib/__tests__/x3dhOracleVectors.test.ts` and `x3dhOracleInterop.test.ts` run in CI job `dr-oracle`. The oracle uses **no libsodium** (Go: `x/crypto/curve25519`, `cloudflare/circl` X-Wing, `x/crypto/blake2b`) so a shared mistake in NYX's own copy cannot pass; scope is X3DH/KEM/kdfChain/AEAD, **not** libsignal's sender-key chain.
- E2E: `pnpm exec playwright test --project=chromium` in `web/`. Prereqs: Postgres + Redis running, server dev (`pnpm --filter nyx-server dev`), vite dev (`pnpm --filter nyx-web dev`). `workers: 1` (serial — suite is flaky in parallel). `e2e/global.setup.ts` wipes the local DB via `server/scripts/reset-test-env.ts`.
- Playwright config webServer uses pnpm filter names `nyx-server` / `nyx-web` (NOT `server`/`web`).

## WebTransport / transport.spec

- Rust sidecar: `cargo build --release` in `server/transport-sidecar`, run with `JWT_SECRET`, `REDIS_URL`, `TRANSPORT_PORT=33333`. It prints a cert hash at startup → paste into `web/.env` as `VITE_TRANSPORT_CERT_HASH` (dev pinning).
- The sidecar is now **lib + bin**: pure protocol (opcode constants, frame classification, HELLO parse/negotiate/reply) lives in `src/protocol.rs`, the deterministic fuzz campaign in `src/fuzz.rs`, the runner in `src/bin/fuzz-framing.rs`; `src/main.rs` only does I/O and imports from `transport_sidecar::protocol`. Add new framing/HELLO logic THERE (with `cargo test`), not inline in the four connection loops — that duplication is what the fuzz targets were built to prevent.
- `transport.spec.ts` / `chat.spec.ts` auto-skip when `WebTransport` is undefined (headless Chromium on this machine lacks it). Use Chrome full build (`--project=chrome`) in CI (`e2e-chrome` job builds + runs the sidecar and parses the cert hash). **Run them for real before trusting them** — while they were skip-only, `transport.spec` carried two bugs (a tombstone assertion that could never match, and `getByText` also matching the sidebar preview so the action hung); scope chat assertions to `main`.
- `web/e2e/call.spec.ts` (WS-E gate) proves a real relay: `/api/keys/turn` coturn credentials → two `iceTransportPolicy: 'relay'` peers connected → selected pair `relay`↔`relay`. It needs coturn running with the server's `TURN_URLS`/`TURN_STATIC_AUTH_SECRET` (local recipe in `docs/11` §11.2; CI `e2e-chrome` installs and starts it); otherwise it skips with a written reason. It drives SDP without trickle ICE — wait for `iceGatheringState === 'complete'` before `setRemoteDescription`, or ICE stalls in `new` and looks like a coturn failure.

## Key Transparency service side

- The KT database (LevelDB) is owned by **exactly one process**: `server/kt-query` (Go). goleveldb's read-only open still takes an OS `LOCK_SH` while the writer holds `LOCK_EX`, so a second process cannot read the same DB (`server/kt-query/store_test.go` guards this). Upstream's `kt-server` binary is therefore no longer deployed; that process serves reads (`/search`, `/distinguished`, `/monitor`, `/config`), the write gRPC service (`KT_SERVER_URL` unchanged), and the `distinguished` key.
- Build/test it with `server/kt-query/build.sh [test]`. It depends on the **private** upstream repo, which cannot be fetched from the network, so the module is **vendored** in `server/kt-query/vendor/` and `go.mod` has **no** `replace` — builds are offline (`-mod=vendor`). `NYX_KT_UPSTREAM=<path>` temporarily switches to a local checkout for pin-chasing.
- The NYX API never parses KT proofs: `/api/keys/kt/*` forwards raw protobuf as base64url and the WASM verifier (`packages/keytrans-wasm`) checks it in the client. Don't add a JS protobuf parser.
- No verdict is trusted without a check: `server/kt-query/build.sh test` (**31 Go tests**: proof/read paths, third-party auditor service, verified snapshots) plus the web KT suite (**74 tests**: `keyTransparency.test.ts` 18, `ktGossip.test.ts` 17, `peerIdentityTrust.test.ts` 14, `ktMonitoring.test.ts` 11, `ktSubject.test.ts` 8, `ktBundleProof.test.ts` 6 — WASM/fixtures through the live adapter, sealed state, fail-closed monitor, split-view verdicts, Dexie adapters).
- Client KT state lives in Dexie tables `ktMonitoring` and `ktGossip` (NyxUnifiedDB **v16**; the two KT tables were added in v13, v14 `ktConfig`, v15 `groupCredentials`, v16 drops `groupCredentials` — both KT tables additive) and is sealed `ENC1:` via `web/src/lib/ktMonitoring.ts` and `web/src/lib/ktGossip.ts`. `runKtMonitorOnce` is **fail-closed**: state is written only after `verifyMonitor` succeeds. The monitor loop (`startKtMonitorLoop`, wired in `App.tsx`) is live; gossip shares the local `(treeSize, root)` anchor inside the sealed message payload (`ktG`, root from `GET /api/keys/kt/head`) and reports `split-view` when two clients see different roots for the same tree size. KT v2 (ML-DSA-65) has its own log/auditor/metrics; the server dual-writes when `KT_V2_SERVER_URL` is set, while reads stay on v1 via `KT_QUERY_URL`. A failed log check is no longer silent: `checkLog` returns verdict `unavailable`, it is stored per peer (`ktLastVerdict`), and `ChatWindow` shows an informational banner (never a send gate) — audit F-09. Still open: upstream `cmd/kt-client` interop, two auditor implementations side-by-side, auditor on the same host as the log, and the read cutover to v2 (`docs/34` §34.6).
- KT snapshots: `server/kt-query` writes verified daily archives (`-snapshot-dir`, copy while writers are paused, reopen + compare tree head/root with the live tree) and `server/src/jobs/ktSnapshot.ts` uploads the newest one to R2 daily with 30-day retention (`KT_SNAPSHOT_DIR`; credentials stay in the server process). See `docs/10` §10.13.
- Local dev gotcha: if the browser has `WebTransport` but the Rust sidecar is NOT running, the burner/transport specs do **not** auto-skip — they fail at `ESTABLISHING_UPLINK`. Start the sidecar or use `--project=chrome`.
- Sidecar ignores opcode `0x00` on uni-streams/datagrams (CHAFF); auth also uses `0x00` but over the bidi control stream. Rust hardcodes opcode numbers — sync with `packages/shared/src/transport.ts`.
- Capability negotiation runs on **both** relays and must stay identical: sidecar bidi HELLO (WT) and the socket.io gateway replying to `handshake.auth.capabilities` (WSS, `server/src/utils/transportCapability.ts`). `SERVER_CAPABILITIES` in `packages/shared` is the single source — removing a capability there disables the feature (e.g. SPQR ratchet v2) on both transports.

## E2EE / crypto constraints (do not break)

- **Do not split** `web/src/workers/crypto.worker.ts`, `crypto-worker-proxy.ts`, or other crypto files (explicit maintainer rule); fix them in place only.
- Frozen formats: at-rest prefix `ENC1:` (keychainDb), XChaCha envelope `base64url(nonce(24)||ct)` (canonical worker ops `xchacha_seal`/`xchacha_open`), `ENCRYPT_DATA` JSON must keep `Array.from(...)` number arrays (JSON.stringify of Uint8Array silently breaks stored bundles), 8KB traffic-cover padding. Never change primitives/padding/protocol.
- Group chain keys / skipped keys / story keys are encrypted at-rest with masterSeed; migration runs on unlock via `saveDeviceAutoUnlockKey`.
- **Zod 4 must run jitless** (prod CSP has no `unsafe-eval`). Set it ONLY via direct mutation `globalThis.__zod_globalConfig.jitless = true` — using `zod.config()` gets tree-shaken in prod builds because zod declares `sideEffects: false`. Done in `packages/shared/src/schemas.ts` and `web/src/zodSetup.ts` (first import in main.tsx). Don't remove, and don't add `unsafe-eval` back to nginx CSP.
- Message pipeline lives in `web/src/lib/messagePipeline.ts` (extracted from the store). Own-message decrypt failures return `waiting_for_key`, never error bubbles.
- **Group key envelopes go through the group mailbox** (`docs/37` §37.3.2): client `web/src/lib/groupMailbox.ts` posts `KEY_ENVELOPE` items tagged `HMAC(memberToken, "nyx-mailbox-v1")`, poll loop wired in `App.tsx`, receive path = `storeReceivedSessionKey`. `group:fulfilled_key` is now a fallback for when metadata/tokens are not in the store yet (e.g. first distribution during `createGroup`) — don't add new senders on it. Server side: `server/src/utils/groupMailbox.ts` + routes in `server/src/routes/groups.ts` (TTL 7 days, epoch filter, GC in `jobs/cleanup.ts`).
- **Group epoch rotation (PCS kasar, `docs/37` §37.3.6)**: `web/src/lib/groupEpochRotation.ts` decides via the pure `groupEpochPolicy.ts` (24 h or 500 messages, admin-only, loop in `App.tsx`), then `POST /api/groups/:id/epoch` + `rotateGroupKey(..., 'periodic_rotation', true, newToken)` so membership metadata carries the new group token. The new token is persisted as `pendingToken` before metadata is written — a retry must reuse it, never rotate twice. `GET /api/groups/:id/epoch` (admin capability) exposes `{epoch, rotatedAt, createdAt, messageSeq}`.
- **Anonymous sync is `POST /api/groups/sync`** (`web/src/lib/groupSync.ts`): token in body, optional Privacy Pass `proofs` (one token = one sync, bound to `conversationId`, `PP_SYNC_REQUIRED=1` to enforce), and OHTTP POST when `VITE_OHTTP_ENABLED=1` (gateway caps that body at 64 KB). Privacy Pass client = `web/src/lib/privacyPass.ts` (Blind RSA, tokens sealed at rest in `kvStore`, 24 h TTL, issuance runs in the background — never block sync on it).
- **Ratchet v2 (braid SPQR) is live beside the frozen v1 path** (`docs/33` §33.10). Header v2 = `{v:2,b:[frames]}` (`web/src/lib/spqrWire.ts`), step orchestration = `spqrSession.ts`, worker ops = `spqr_ratchet_init/encrypt/decrypt` (WASM `packages/spqr-wasm/dist/spqr.wasm`, loaded lazily from an asset URL — never imported into the main bundle, precached by the SW via `**/*.wasm`), braid state = `spqrState.ts` rows `nyx_spqr_state_v1:*` (`ENC1:`). **v2 is only sent after the peer proves it can read it** (`ackV: 2` inside the sealed payload); v1 header shape, primitives and padding must NOT change. Kill switch `VITE_SPQR_FORCE_V1=1` (plus a DEV-only runtime override `localStorage['nyx_spqr_force_v1']` in `spqrNegotiation.ts`, read per send); a kill switch stops **sending and advertising** v2, never reading it — stranded v2 messages must stay readable. The sidecar must keep `spqr-ratchet` in `SERVER_CAPABILITIES` for the deployment gate.
- E2E for v2: `web/e2e/spqr.spec.ts` (upgrade to v2 **and** the two-client rollback test). Without a sidecar (no negotiated capability) start the dev server with `VITE_SPQR_FORCE_V2=1` (override honored only in DEV builds); the spec skips with a written reason when v2 is not active in that environment. The rollback test hardcodes the kill-switch key and asserts it equals `spqrNegotiation.SPQR_RUNTIME_KILL_SWITCH_KEY` — keep them in sync.

## Server gotchas

- ESM TS with `.js` import specifiers (run with `tsx`). `utils/` holds shared helpers (`sessionUtils.ts`, `validate.ts` incl. `safeEqualStrings`).
- Prisma 7: `prisma db push` (no migrate flow) reads `DIRECT_URL || DATABASE_URL` via `prisma.config.ts`; pass `--url` explicitly if env isn't loaded. Prisma 7 refuses db push without `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` env (AI guard) — set it in scripts/CI, ask a human first.
- `server/src/lib/prisma.ts` appends `sslmode=require` ONLY for non-local hosts — local Postgres must stay plaintext (self-signed snakeoil cert otherwise kills every query with `TlsConnectionError`). Do not regress this.
- Rate limiting uses atomic Lua INCR+EXPIRE (`redisBridge.ts` RATE_LIMIT_LUA, auth pow, sandbox newchat) — do not reintroduce incr-then-expire races.
- Single-active-device check runs per-opcode in `redisBridge.ts` (`isActiveDeviceAllowed`, 60s cache). CSRF server state is keyed per client via `x-nyx-installation-id` header (app.ts) — client `web/src/lib/api.ts` must send that header consistently (same value as `getPersistentInstallationId()`), or login/register break with 403.
- Session/CSRF cookies come from ONE place: `authCookieOptions()` (`server/src/utils/sessionUtils.ts`, used by set **and** clear) + `COOKIE_DOMAIN`. The official deployment splits origins (REST relative on `app.*`, relay at `api.*`), so a host-only cookie means the socket.io handshake is rejected `unauthorized` and the client hangs on `ESTABLISHING_UPLINK` — the 2026-10-25 incident, docs/10 §10.20. The WSS path also sends `handshake.auth.token`, so realtime auth does not depend on cookie scope. Related: `deploy.yml` starts pm2 **without** `NODE_ENV`, so the VPS process reports `development` until that env is set in `/root/nyx-app/.env`.
- Redis pub/sub: `nyx:upstream:<opCode>` / `nyx:downstream`. Relay payloads must NOT duplicate `content` into a `ciphertext` field (`mappers.ts`).
- Group route authorization lives in **testable utils**, not inline in `routes/conversations.ts`: admin capability checks in `utils/adminCapability.ts`, group membership/leave/details/rotation/purge in `utils/groupAccess.ts` (+ `tests/groupAccess.test.ts` locks the exact status codes and gate ORDER: token → admin → member count). Status strings are client contract (`BLIND_AUTH_REQUIRED: …`, `ADMIN_AUTH_REQUIRED: …`, `MEMBERS_REMAIN: …`) — note `PUT /:id/details` answers **403 (not 404)** for a missing conversation, keep it that way. Credential issuance/group blind-RSA (Fase 5–6) was removed on 2026-10-23; do not reintroduce it into this route.
- **Sealed at-rest values have two formats**: legacy bare base64url (key id `0`, from `NYX_AT_REST_PEPPER`) and `ENC2:<keyId>:<payload>` (key ring `NYX_AT_REST_KEYRING` / `_FILE`). Always look sealed columns up with `sealedLookupCandidates()` (`{ in: … }`), never a single `sealAtRest()` value, or rows written under the other key silently disappear after a rotation. `scripts/reseal-at-rest.ts` (dry-run default, `--apply`) migrates rows; runbook docs/10 §10.17. Blind-index HMACs are NOT rotatable server-side (one-way, no plaintext stored).
- Group admin capability (RBAC): the server stores only `Conversation.adminSecretHash` (SHA-256 of the 256-bit `X-Admin-Token` header); guard = `requireAdminCapability` (`server/src/utils/adminCapability.ts`) on `PUT /:id/details`, `POST /:id/key-rotation`, `DELETE /:id/group`. **NULL hash = fail-closed** (no admin operations without a capability hash). `DELETE /:id/group` purges the group and answers 409 `MEMBERS_REMAIN` while delivery tokens still exist. New columns REQUIRE the `prisma db push` on the VPS to have run before new clients are rolled out.

## Ponytail (lazy senior dev mode)

Installed from https://github.com/DietrichGebert/ponytail — full ruleset in `.agents/skills/ponytail/SKILL.md`; the commands live beside it as the skills `ponytail-review`, `ponytail-audit`, `ponytail-debt`, `ponytail-gain`, `ponytail-help`. Active every session until the user says "stop ponytail"; levels `lite` / `full` (default) / `ultra`.

The best code is the code never written. Read the code the change touches and list every place it must reach (callers, tests, fixtures, config, exports) — that is scope; extra features are not. Then take the first rung that fully works:

1. Does it need to exist? Skip what nobody asked for, and name it in one line.
2. Already in this codebase (helper, component, pattern)? Use it the way the surrounding code does.
3. Standard library or platform feature? Use it, unless the project has its own.
4. Already-installed dependency? Use it; never add one for a few lines.
5. Can it be one line a reader gets at a glance? One line.
6. Otherwise the minimum code that works.
